# v4.1：先修传力，再修爽感

## 诊断

“看着不爽”和“玩着不爽”是两组问题，不能用更多粒子一起遮过去。

### 看着：没有视觉主角

机架边框、浅银推板、后墙和硬币都在争夺亮度。规则行列的币面像陈列品，而不是受力、堆叠、将要坍塌的币堆。镜头持续横向呼吸，大奖金币的高 bumpScale 又产生高光噪点。手机的装币按钮还存在子元素深色字覆盖亮字的问题。

改动：机架与金属压暗、减少辉光、金币保留暖色高光与投影、下层错列与局部叠层、修正大金币材质。手机略微倾斜，让币厚和上下层关系可见；镜头漂移收敛。保留已有角色图与场景，不再叠加无关装饰。

### 玩着：投入和回报之间有空转

旧上层两行都在后段；在部分台面状态下，币跟着推板往返，前沿却得不到压力。横向投币的碰撞是真实的，但后续向下层传递的过程太弱。下层过于规整，容易出现长时间积币、很少前沿落币的体验。

改动：三行上层币堆桥接到回缩前沿；重新设置下层错列位置和叠层；适度下调币／板摩擦并提高推板循环速度。所有硬币仍是 Rapier 动态刚体，没有逐帧指定落点、追踪目标或自动向前加推力。初始布局与调参集中在 `src/machine-tuning.js`。

### 节奏：低帧时被截成慢动作

旧主循环将每帧计时截到 50ms，且物理最多三步。在帧耗时更长时，投币连发、推板和奖励节奏都会一起变慢。软件 WebGL 的测试环境能暴露这个行为，但不能用它的帧率代表用户手机。

改动：单帧最多 100ms，固定 60Hz 物理最多六步；持续慢帧时降低画布和后处理分辨率、关闭辉光，先保交互。低于 10fps 或长时间挂起仍进行限时保护；没有承诺所有设备满帧。

### 反馈：有装饰，缺少明确因果

增加推进／回收读数、侧投硬币真实落入下层时的短促碰撞反馈，以及真实前沿入账后的金色灯带与连续收币数量。已有收币批次按金额／数量分级；中、大批次再触发不同强度的震动。减少投币瞬间的小幅乱晃，让“入账”比“按键”更有重量。

## 保留与兼容

- 普通币只有左右入口；双投仍消费两次普通额度。
- 上层全程真实横滑／接触／跌落，无固定终点。
- 特殊币独立库存、限量挑战、三船员、三难度、八关商店、航海档案不改规则。
- 沿用 v6 存档格式与原键。旧局原币堆位置保留，新布局仅对新局生效；摩擦、节奏与表现对继续游戏也生效。
- 没有为了演出自动补币、自动加分或脚本判赢。

## 验证方法

- `npm test`：规则、双槽原生物理、奖励守恒、轮盘几何／队列、航海档案。
- `npm run test:mobile`：手机、小屏、横屏、平板、桌面布局、命中区、轮盘与机台层级。
- `npm run test:experience`：船员、难度、实际联动、存档幂等、八关与无尽状态流。该套件包含人为构造状态，不能作为自然通关平衡证据。
- `npm run test:rewards`：奖励排队与发放守恒。
- `npm run test:feel`：固定种子、每半秒双侧同投、不强改分数、不调用 `onWin`，观察真实传力与前沿入账；同时验证静置不白赢、普通额度不返还、100ms 物理补步。`QA_DIR` 可留存画面与测试证据。

这是一次基础手感修复，不等于已经验证全部构筑／八关的长期平衡，也不以单个随机种子宣称稳定通关率。下一轮应以玩家实际设备和完整局反馈继续调校，而不是继续堆系统。
